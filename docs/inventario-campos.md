# Inventário de campos de entrada — backend Ampara

Branch `feat/integrar-cadastro-e-prontuario`, base `main` (`f6c79ae`). Reconstruído em 2026-10-22 por leitura direta do código (DTOs, controllers, services, `schema.prisma`, migrations, seed, scripts e `contracts/openapi.json`). Cada afirmação cita o arquivo que a sustenta. A execução dos testes está em `relatorio-validacao-tecnica.md`.

## Como ler

- **Frontend:** não existe neste repositório. † em "Nome apresentado" significa **"Rótulo de interface não confirmado — inferido pelo domínio"**. Nenhuma tela, botão ou posição visual foi inventada.
- **Etapa do fluxo:** F1 cadastro de animal, F2 responsável, F3 evento de saúde, F4 atendimento clínico, F5 prontuário PDF, F6 foto, F7 auditoria/administração, F8 outros (ver `fluxos-de-trabalho.md`).
- **Origem do valor:** U = digitado/enviado pela pessoa; C = selecionado de catálogo; A = automático; D = derivado; I = integração; X = interno/controle.
- **Permissão:** "Autenticado" = qualquer conta ativa na API; "Unidade" = conta com acesso à unidade do animal (ADMIN acessa todas); "ADMIN" = papel `ADMIN`. Papéis reais: `ADMIN` e `OPERADOR` (`enum PapelUsuario`, `schema.prisma`).
- **Validação "Não identificada"** = não há decorador nem regra no código.
- O `ValidationPipe` global (`src/configurar-aplicacao.ts`) usa `whitelist`, `transform` e `forbidNonWhitelisted`: **campo desconhecido no body/query gera 400**.
- `PATCH` de animal e de responsável usa `PartialType`: todos os campos ficam opcionais; `null` passa no `IsOptional`. Para animal, `AnimalsService.atualizar` rejeita `null` nos 5 campos obrigatórios; os demais aceitam `null` para limpar.

## 7. Resumo quantitativo e método

**Método:** cada par (recurso, nome técnico) conta **uma vez**, mesmo aparecendo em criação, edição e resposta.
